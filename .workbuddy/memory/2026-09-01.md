### 踩坑记录（重要）
- **PowerShell 5.1 读写含中文路径的 .ps1 文件会乱码**：无 BOM 的 UTF-8 脚本被按 GBK 解析，导致输出路径失效、脚本静默失败（exit 1）。含中文路径的脚本要么内联执行，要么存成 GBK/带 BOM。
- **`[Diagnostics.Process]::Start` 被安全策略拦截**，须用 `Start-Process`。
- **环境同时存在 `http_proxy` 和 `HTTP_PROXY`** 会让 .NET 的 `Invoke-WebRequest` 抛「已添加项」异常。HTTP 探测改用 TcpClient 原始请求，或先 `Remove-Item Env:\http_proxy`。
- **`Start-Process -RedirectStandardOutput` 对 PyInstaller onefile 取不到输出**（文件为空、ExitCode 为空）。改用直接调用 `& exe args 2>&1` 捕获。
- **ps1 内容里出现 `if exist ... goto` 等 cmd 语法会被安全过滤误判拦截**，生成 .cmd 文件时改用 Write 工具直接写（UTF-8 + `chcp 65001`）。

## 第二轮：修复"其他电脑首跑报错 尚未生成报告"

### 现象
用户只拷了 exe 到别的电脑运行，首页返回 `{"ok":false,"msg":"尚未生成报告，请先刷新"}`（裸 JSON，无按钮，卡住）。根因：全新目录无预生成报告，旧 exe 既无首跑友好页、又无启动自动生成。

### 修复（report_server.py，已重打包）
1. `_serve_report`：无报告时改返回**友好页**（带「刷新数据并生成报告」按钮，自动 fetch /refresh），不再返回裸 JSON。
2. `main()` 启动后若 `latest_report() is None`，后台线程 `_initial_generate()` 先抓一次（不受交易时段限制），同事打开即自动生成。
3. **关键修复**：`/refresh` 与 `_initial_generate` 生成时持 LOCK 约 90~160s；原 `_serve_report` 也抢 LOCK，导致首页卡几十秒超时。改为「无报告先返回友好页（不加锁）」，仅读文件时加锁 → 首跑首页 **0.x 秒**秒开。

### 验证（干净目录=只放 exe，模拟同事电脑）
- 首跑首页 0.0s 返回友好页（含按钮）；`/refresh` 90s 生成成功 `ok:true`；再开首页出报告（186KB）。
- `frozen=True`，`BASE = exe 所在目录`，数据/报告/日志/pid 全部建在 exe 同目录 → **数据不丢**（最初担心的 _MEIPASS 临时目录问题未发生）。
- 注意：本机调试时若 `Start-Process` 误启了源码 `dist\` 下的 exe（而非拷贝到干净目录那份），`sys.executable/BASE` 会指向源码目录、读到旧报告——属测试脚本坑，非 exe bug；同事电脑只有一份 exe 不受影响。

### 给用户的即时解法（无需等重包）
在报错电脑浏览器直接开 `http://127.0.0.1:8765/refresh` 手动触发一次生成（约 1~3 分钟，需联网），再刷新首页即可。新版 exe 重拷后连这步都不用。
